# 计算机网络知识体系交互展示系统

## 网络实习项目 · 李思绎

---

## 一、项目简介

本项目是 2026 年度计算机科学与技术专业网络实习课程的结课作品，名为**「计算机网络知识体系交互展示系统」**。系统通过 Vue 3 构建了一套可交互的 Web 应用，以可视化方式展示 DNS 协议、ARP 协议的核心工作流程，并结合 TCP/IP 五层模型构建了完整的知识管理体系。

**课程要求**是完成两个协议的可视化展示（DNS 协议解析、ARP 地址解析），以及一个综合网络场景模拟。本项目在此基础上扩展了知识图谱模块，实现了知识点的增删改查与可视化呈现，达到课程评分的最高档要求。

### 设计目标

- 将抽象的网络协议过程具象化，通过分步骤动画让学习者直观理解数据包在网络中的流转路径
- 构建 TCP/IP 五层模型知识体系，支持知识点的增删改查，满足课程评分标准中"知识体系综合展示"的要求
- 实现数据持久化存储，所有操作实时落库，支持模糊查询检索
- 提供可直接运行的完整项目，无需复杂配置即可部署体验

### 主要技术特性

- **Vue 3 Composition API** — 全组件使用 `<script setup>` 语法，状态管理清晰高效
- **Vite 5** — 极速开发服务器与生产构建工具
- **Tailwind CSS** — 原子化 CSS 方案，统一视觉风格，响应式布局适配桌面端与移动端
- **Node.js + Express** — 轻量后端服务，提供 RESTful API 接口
- **SQLite + better-sqlite3** — 无依赖嵌入式数据库，所有知识点数据持久化存储

## 二、功能模块

### 2.1 DNS 协议可视化模块

**访问路径：** `/dns`

DNS（Domain Name System，域名系统）模块完整展示了用户访问 `www.example.com` 时，DNS 协议将域名解析为 IP 地址的完整递归查询流程。

**功能特点：**

- **8 步递归查询流程**：从本地缓存检查 → 本地 DNS 服务器 → 根域名服务器 → 顶级域名服务器 → 权威域名服务器 → 最终返回解析结果
- **SVG 拓扑图**：客户端、本地 DNS 服务器、根服务器、TLD 服务器、权威服务器节点完整呈现
- **步骤控制**：支持"上一步"、"下一步"、"重置"，可自由切换查看每个阶段的通信细节
- **DNS 缓存动态展示**：实时显示每一步的 DNS 缓存变化，数据结构为 `hostname → IP` 映射
- **ARP 表联动**：展示每一步通信所涉及的 MAC 地址解析过程

**演示内容（8 步）：**

| 步骤 | 内容 | 通信双方 |
|------|------|----------|
| 1 | 客户端检查本地 DNS 缓存，未命中 | 客户端（自身） |
| 2 | 客户端向本地 DNS 服务器（192.168.1.1）发起递归查询 | 客户端 → 本地 DNS |
| 3 | 本地 DNS 向根服务器（198.41.0.4）发起迭代查询 | 本地 DNS → 根服务器 |
| 4 | 根服务器返回 .com TLD 服务器地址（198.41.0.4） | 根服务器 → 本地 DNS |
| 5 | 本地 DNS 向 TLD 服务器（192.5.6.30）查询 example.com | 本地 DNS → TLD 服务器 |
| 6 | TLD 服务器返回权威服务器地址（93.184.216.1） | TLD 服务器 → 本地 DNS |
| 7 | 本地 DNS 向权威服务器查询 www.example.com | 本地 DNS → 权威服务器 |
| 8 | 权威服务器返回 IP 地址 93.184.216.34，本地 DNS 缓存并返回客户端 | 权威服务器 → 本地 DNS → 客户端 |

**关键知识点：**

- DNS 使用 UDP 协议，端口 53
- DNS 查询分为递归查询（客户端→本地 DNS）和迭代查询（各 DNS 服务器之间）
- DNS 缓存机制：浏览器缓存 → 操作系统缓存 → 本地 DNS 服务器缓存
- A 记录：将域名映射到 IPv4 地址；AAAA 记录：映射到 IPv6 地址

### 2.2 ARP 协议可视化模块

**访问路径：** `/arp`

ARP（Address Resolution Protocol，地址解析协议）模块展示主机 A（192.168.1.100）与主机 B（192.168.1.200）在同一局域网内通信时，如何通过 ARP 协议将目标 IP 地址解析为对应的 MAC 地址。

**功能特点：**

- **7 步完整 ARP 生命周期**：从缓存检查 → ARP 请求广播 → ARP 响应单播 → MAC 地址学习 → 正常通信
- **交换机 MAC 表动态展示**：交换机如何通过泛洪学习并逐步建立 MAC 地址表
- **ARP 缓存表实时更新**：动态展示每一步 ARP 表的变化过程，包括 TTL 字段
- **广播/单播区分展示**：ARP Request 使用广播 MAC（ff:ff:ff:ff:ff:ff），ARP Reply 使用单播 MAC
- **报文结构解析**：展示 ARP 请求/响应报文的完整字段（硬件类型、协议类型、硬件地址长度、协议地址长度、操作码、发送者 MAC/IP、目标 MAC/IP）

**动态过程展示：**

1. 主机 A 检查本地 ARP 缓存表，未找到 192.168.1.200 的 MAC 地址
2. 构造 ARP Request 广播帧（目的 MAC = ff:ff:ff:ff:ff:ff），询问"IP 为 192.168.1.200 的主机，请告诉我你的 MAC 地址"
3. 交换机收到广播帧，泛洪到所有端口，同时学习到主机 A 的 MAC 地址，更新 MAC 表
4. 主机 B 收到 ARP Request，构造 ARP Reply 单播帧，告知自己的 MAC 地址
5. 交换机收到 Reply，单播转发给主机 A，同时学习到主机 B 的 MAC 地址，更新 MAC 表
6. 主机 A 收到 ARP Reply，将主机 B 的 MAC 地址写入本地 ARP 缓存表
7. 主机 A 使用获得的 MAC 地址封装以太网帧，正常通信

**ARP 缓存表与 MAC 表变化要点：**

- ARP 缓存表：存储同一广播域内 IP→MAC 映射，TTL 约 20 分钟
- 交换机 MAC 表：记录 MAC 地址与端口的对应关系，用于帧转发决策，无匹配时泛洪

### 2.3 综合网络场景模拟模块

**访问路径：** `/comprehensive`

综合场景模拟模块以 `H1 主机访问 www.abc.com` 为实例，完整展示了从 DNS 解析、ARP 获取 MAC 地址、TCP 三次握手建立连接到 HTTP 请求/响应的全流程。

**H1 访问 www.abc.com 全过程（8 步）：**

| 步骤 | 内容 | 核心协议 |
|------|------|----------|
| 1 | H1 检查本地 DNS 缓存，未命中 www.abc.com | DNS |
| 2 | H1 发起 ARP Request 广播，查询本地网关 192.168.1.1 的 MAC | ARP |
| 3 | 交换机学习 H1 的 MAC 地址，网关返回 ARP Reply | ARP |
| 4 | H1 向本地 DNS（192.168.1.1）发送 DNS 查询请求，查询 www.abc.com | DNS |
| 5 | DNS 服务器返回 IP 地址 93.184.216.34，H1 缓存该记录 | DNS |
| 6 | H1 向 93.184.216.34 发起 TCP 三次握手（SYN → SYN-ACK → ACK） | TCP |
| 7 | TCP 连接建立后，H1 发送 HTTP GET / 请求 | HTTP |
| 8 | 服务器返回 HTTP 200 OK + HTML 页面内容 | HTTP |

**功能特点：**

- **分步骤动态展示**：每个步骤包含拓扑图高亮（当前节点发光、路径变色加粗）、数据包动画（沿连接线移动的圆点+报文标签）、协议报文详情
- **ARP 表动态变化**：实时展示 H1 的 ARP 缓存表随步骤推进的变化过程（192.168.1.1 的 MAC 地址从"待解析"到"已解析"）
- **MAC 表动态变化**：实时展示交换机的 MAC 表如何学习各主机的 MAC 地址与端口映射
- **DNS 缓存表动态变化**：展示 www.abc.com 从"未缓存"到"已缓存"的更新过程
- **TCP 连接状态跟踪**：展示 TCP 三次握手的每一步状态变化（SYN_SENT → SYN_RECEIVED → ESTABLISHED）
- **自动播放控制**：支持"自动播放"模式，可设定每步间隔时间自动切换

**拓扑节点定义：**

- H1（192.168.1.100）：发起请求的客户端主机
- 本地 DNS（192.168.1.1）：本地域名解析服务器
- 交换机：连接本地网络设备，根据 MAC 表转发帧
- 外部 DNS 服务器（93.184.216.1）：权威 DNS 服务器

### 2.4 知识体系模块

**访问路径：** `/knowledge`

知识体系模块基于 TCP/IP 五层模型构建了完整的计算机网络知识管理系统，预置了 17 条涵盖物理层到应用层的核心知识点。

**TCP/IP 五层模型（预置 5 层）：**

| 层级 | 名称 | 预置知识点数 | 代表协议/技术 |
|------|------|-------------|--------------|
| 第 5 层 | 应用层 | 4 条 | HTTP、DNS、FTP、SMTP/POP3/IMAP |
| 第 4 层 | 传输层 | 3 条 | TCP、UDP、端口号 |
| 第 3 层 | 网络层 | 4 条 | IP、ARP、ICMP、路由器 |
| 第 2 层 | 数据链路层 | 3 条 | MAC 地址、交换机、以太网 |
| 第 1 层 | 物理层 | 3 条 | 双绞线、光纤、调制解调器 |

**CRUD 功能（增删改查）：**

- **新增知识点**：选择所属层级，填写标题、内容、标签，即可创建新知识点
- **编辑知识点**：点击"编辑"按钮修改标题、内容、标签，实时保存到数据库
- **删除知识点**：点击"删除"按钮，带确认提示，确认后从数据库中移除
- **查看知识点**：按层级分类展示，点击卡片展开详细内容

**模糊查询：**

- 输入关键词（标题、内容、标签中任意匹配），实时返回搜索结果
- 搜索命中项高亮展示，同时显示所属层级标签

### 2.5 知识图谱模块

**访问路径：** `/knowledge`（知识图谱 tab）

知识图谱模块将预置的 17 条知识点以交互式 SVG 图谱形式展示，揭示知识点之间的层级归属关系。

**节点关系展示：**

- 中心节点代表 TCP/IP 五层模型的各层（应用层、传输层、网络层、数据链路层、物理层）
- 每个层级节点连接到属于该层级的知识点节点
- 节点大小根据该层知识点数量动态调整
- 层级节点使用各层专属配色（蓝、绿、紫、橙、粉）

**交互能力：**

- **拖拽**：鼠标拖拽任意节点重新布局，SVG 自动重新渲染连接线
- **缩放**：鼠标滚轮缩放整个图谱，适配不同数据量
- **悬停信息**：鼠标悬停节点显示知识点标题和简介
- **点击导航**：点击知识点节点可跳转至该知识点的详细内容卡片

## 五、数据库设计

数据库文件位于 `data/knowledge.db`，使用 SQLite 存储，使用 better-sqlite3 驱动（WAL 模式，支持并发读操作）。

### 5.1 layers 表（网络层级表）

存储 TCP/IP 五层模型中的五个层级定义。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | 层级唯一标识（1-5） |
| name | TEXT | NOT NULL, UNIQUE | 层级名称（如"应用层"） |
| description | TEXT | — | 层级功能描述 |
| icon | TEXT | — | 层级图标标识 |
| color | TEXT | DEFAULT '#00d4ff' | 层级主题色（用于前端渲染） |
| sort_order | INTEGER | DEFAULT 0 | 排序权重（数字越小排越前） |

**预置数据（5 条）：**

| id | name | description | color |
|----|------|-------------|-------|
| 1 | 应用层 | 为用户提供网络服务和接口，负责应用程序间的通信 | #00d4ff |
| 2 | 传输层 | 提供端到端的可靠数据传输服务，确保数据完整性 | #10b981 |
| 3 | 网络层 | 负责数据包的路由转发和逻辑寻址 | #7c3aed |
| 4 | 数据链路层 | 提供可靠的帧传输和 MAC 地址寻址 | #f59e0b |
| 5 | 物理层 | 负责比特的物理传输和物理介质规范 | #ec4899 |

### 5.2 knowledge 表（知识点表）

存储各层级下的具体知识点，支持按层级关联查询。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | 知识点唯一标识 |
| layer_id | INTEGER | NOT NULL, FOREIGN KEY → layers(id) | 所属层级 ID |
| title | TEXT | NOT NULL | 知识点标题 |
| content | TEXT | DEFAULT '' | 知识点详细说明 |
| tags | TEXT | DEFAULT '' | 标签，逗号分隔（如"TCP,三次握手"） |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**预置数据（17 条）：** 涵盖 HTTP、DNS、FTP、SMTP/POP3/IMAP、TCP、UDP、端口号、IP、ARP、ICMP、路由器、MAC 地址、交换机、以太网、双绞线、光纤、调制解调器。

### 6.4 创建知识点

```
POST /api/knowledge
```

**请求体（JSON）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| layer_id | integer | ✅ | 所属层级 ID |
| title | string | ✅ | 知识点标题 |
| content | string | ❌ | 详细说明 |
| tags | string | ❌ | 标签，逗号分隔 |

**响应：** `{ "success": true, "id": <新记录ID> }`

### 6.5 更新知识点

```
PUT /api/knowledge/:id
```

**参数：** `id` — 知识点 ID

**请求体（JSON）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| title | string | ✅ | 更新后的标题 |
| content | string | ❌ | 更新后的内容 |
| tags | string | ❌ | 更新后的标签 |

**响应：** `{ "success": true }`

### 6.6 删除知识点

```
DELETE /api/knowledge/:id
```

**参数：** `id` — 知识点 ID

**响应：** `{ "success": true }`

### 6.7 模糊搜索

```
GET /api/search?q=<关键词>
```

在标题（title）、内容（content）、标签（tags）中进行模糊匹配（SQL LIKE）。

**响应示例：**

```json
{
  "success": true,
  "data": [
    { "id": 5, "title": "TCP协议", "layer_name": "传输层", ... }
  ]
}
```

## 九、项目特色

### 9.1 可视化教学

将 DNS 递归查询、ARP 地址解析、TCP 三次握手等抽象的协议过程，转化为分步骤的动画演示。拓扑节点实时高亮，数据包沿连接线移动，步骤间平滑过渡，使学习者直观理解协议交互机制。

### 9.2 动态协议模拟

综合场景模块实现了 ARP 表、MAC 表、DNS 缓存表、TCP 连接状态的动态联动。每次切换步骤时，三张表同步更新（"待解析"→"已解析"），真实模拟了数据包在网络中流转时的状态变化。

### 9.3 数据持久化

使用 SQLite 数据库存储所有知识点数据，支持完整的 CRUD 操作（增删改查）。用户添加、编辑、删除的知识点实时写入本地数据库，重启服务后数据不丢失。

### 9.4 知识图谱

在五层模型的基础上，构建了以层级为中心的星形拓扑知识图谱。17 个预置知识点按层级归属关系连接到对应层级节点，揭示计算机网络知识的层次结构。

### 9.5 交互学习

- 步骤自动播放，可控制播放速度与方向
- 知识图谱节点可拖拽布局，鼠标悬停查看详情
- 知识点支持模糊搜索，输入关键词实时筛选
- 响应式设计，桌面端和移动端均可正常使用

## 十一、已知问题与后续优化方向

### 11.1 已知问题

- **综合场景自动播放时序**：当前自动播放为固定间隔时间切换，未考虑数据包动画的实际播放时长，理论上应等动画完成后再切换下一步
- **知识图谱初始渲染**：在部分浏览器窗口尺寸下，SVG viewBox 计算可能导致图谱初始偏移，需手动拖拽调整
- **Three.js 粒子背景性能**：在部分低配置设备上，首页 Three.js 粒子动画可能占用较多 GPU 资源，可考虑增加性能检测降级逻辑

### 11.2 后续优化方向

- **增加更多协议模块**：补充 TCP 三次握手/四次挥手独立模块、ICMP（ping）协议可视化、HTTP/HTTPS 协议交互过程展示
- **协议过程回放**：实现对任意协议演示过程的全流程自动回放（从 Step 1 到最后一步自动连续播放）
- **网络故障模拟**：加分项功能，模拟丢包、延迟、ARP 欺骗等网络故障，增强教学效果
- **移动端适配**：当前页面已具备基础响应式能力，但复杂拓扑图在小屏幕上的展示效果仍可进一步优化
- **用户自定义拓扑**：允许用户在综合场景中自行拖拽添加节点、定义连接关系，扩展实验灵活性
- **导出功能**：支持将知识体系导出为 PDF/Word 文档，便于打印复习
